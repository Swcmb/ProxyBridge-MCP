# ProxyBridge 路由语义

## 匹配顺序

规则按数组索引顺序从上到下匹配，**首个命中的规则生效**，后续规则不再求值。

```
rules[0] → 优先级最高
rules[1]
rules[2]
...
rules[n] → 优先级最低
```

### 最佳实践
- 将更具体的规则放在前面
- 将通用的规则（如 `*` 匹配所有）放在后面作为兜底
- 避免规则重叠导致意外行为

## localhost 旁路

ProxyBridge 默认会旁路 localhost 流量，即使配置了匹配 localhost 的规则。

- `127.0.0.1`、`::1` 等本地回环地址不会被代理
- 如需强制代理本地流量，需在 GUI 中启用「LocalhostViaProxy」选项

## 强制直连地址段

以下地址段会被强制直连，PROXY 动作无效：

### IPv4
- `255.255.255.255` — 广播地址
- `x.x.x.255` — 子网广播地址
- `224.0.0.0` - `239.255.255.255` — 组播地址
- `169.254.0.0/16` — APIPA/链路本地地址
- UDP 端口 67/68 — DHCP 客户端端口

### IPv6
- `FF00::/8` — 组播地址
- `FE80::/10` — 链路本地地址
- `FEC0::/10` — 站点本地地址（已弃用）
- `::` — 未指定地址
- UDP 端口 546/547 — DHCPv6 客户端端口

### 注意事项
- 域名类 token 与 IP 类强制直连段不可比，静态分析无法判定，由运行期处理
- 代理域名指向这些地址时，静态分析不会报错，但实际流量可能被旁路

## 规则遮蔽检测

当后置规则被前置规则完全覆盖时，校验器会发出 `RULE_SHADOWED` 警告。

### 判定条件
- 前置规则的所有字段都是后置规则字段的超集
- 至少有一个字段是严格超集（不是完全相同）

### 示例
- `rules[0]`: ProcessName=`*`, TargetHosts=`*`, TargetPorts=`*`, Protocol=`BOTH`, Action=`PROXY`
- `rules[1]`: ProcessName=`chrome.exe`, TargetHosts=`*`, TargetPorts=`*`, Protocol=`TCP`, Action=`PROXY`

`rules[1]` 会被 `rules[0]` 完全遮蔽，永远不会被求值。

## 禁用规则

禁用的规则（IsEnabled=false）不会被求值，也不会参与遮蔽检测。
